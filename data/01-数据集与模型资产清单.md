### 1.7 ⚠️ 数据划分的已知缺陷

| 缺陷 | 数值 | 影响 |
|:---|:---|:---|
| **`data12` 验证集泄漏** | `train ∩ val = 264` 张，另有 96 张 val 在 train 里有 `_r2` 孪生 | 验证 mAP50 虚高 |
| `data12` 未进入任何 split 的标签 | 950 个 | 数据浪费 |
| `data10` 过采样累积失控 | 7240 张（其他轮 ~2180），`_r2`~`_r12` 共 11 种后缀 | 该轮训练分布与其他轮不可比 |

> 对照：`step7/data4` **没有**这种重叠（它的划分是一次 shuffle 后的不相交切片）✅

### 1.8 ⚠️ 过采样脚本已丢失

**整个仓库里不存在任何过采样代码。**

对所有 `*.py`（排除 `PaddleDetection`、`result_sample`、`site-packages`）grep `_r2` / `_r{` / `suffix` / `defaultdict` / `random.sample` —— **零匹配**。没有 `build*.py` / `*sample*.py`，没有任何脚本引用 `data12` / `labelme_dataset12`，`data12`~`data15` **没有 `code/` 目录**（对比 `data1`~`data6` 都有）。

**⇒ 生成 `data12` 的那个脚本没有被保留。只有数据和文档幸存。**

策略因此只能**从产物反推**（下表即反推结果，算术可精确对账）：

| 项 | 数值 | 推导 |
|:---|:---|:---|
| val | **472** | 精确等于 `sorted(all_stems)[0::6]`；全部有标注；**无 `_r2`** |
| train images | **2179** | = 1669 base + **510 `_r2`** |
| `_r2` 数 | **510** | 精确等于文档记载的 510 张多框图 ⇒ **多框 ×2 确认** |
| 不在 train/images 的 label 数 | **1158** | ≈ 2315 单框图 / 2 = 1157.5 ⇒ **单框 50% 欠采样确认** |
| train labels | **2177** | = 510 + 510 + 1157 |
| train 中仅有的 2 张无标签图 | `frame_000491`, `frame_001103` | 零框负样本，全部保留 |

## 二、模型文件大小（字节级实测）

| 模型 | 文件 | 大小 |
|:---|:---|:---|
| YOLOv8m PyTorch | `best.pt` | 49.6 MB |
| YOLOv8m ONNX (640, Step5) | `best.onnx` | 103,625,064 B (98.8 MB) |
| YOLOv8m ONNX (512, Step6) | `best.onnx` | 101,137.3 KB |
| YOLOv8m ONNX (640, Step9) | `best.onnx` | 101,161.8 KB |
| Step5 Paddle | `model.pdmodel` | **158,386 B** (155 KB) |
| Step5 Paddle | `model.pdiparams` | **103,534,112 B** (98.7 MB) |
| Step6 P2 Paddle | `model.pdmodel` | **168,162 B** (164 KB) |
| Step6 P2 Paddle | `model.pdiparams` | **103,473,632 B** (98.66 MB) |
| Step9 Paddle | `model.pdmodel` | **198,251 B** (193.6 KB) |
| Step9 Paddle | `model.pdiparams` | **103,534,304 B** (98.74 MB) |
| A 榜 PP-YOLOE+ CRN-S | `model.pdmodel` | 164~190.8 KB |
| A 榜 PP-YOLOE+ CRN-S | `model.pdiparams` | 28.6~29.3 MB |

**关键差异**：
- P1 的 `model/` 与 `step5/model/` **字节完全一致**（103,534,112 / 158,386），即 **P1 复用未改的 640 模型** —— P1 是纯粹的后处理改动。
- P2 的 512 模型是**真正重新导出的**（参数量不同：103,473,632 vs 103,534,112）。

## 三、模型权重索引

| 阶段 | 权重路径 | 说明 |
|:---|:---|:---|
| Step1 | `step1/weights/model_best.pth` | Faster R-CNN 教师模型（伪标签生成器） |
| Step4 | `step5/best1/yolov8m_AdamW_1e-4/train/weights/best.pt` | mAP50 0.9888，"最优"（但排名是噪声） |
| Step7 | `step7/result/model_v4/train/weights/best.pt` | mAP50 0.9877，49.6 MB |
| Step8 | `step8/result/model_v12/train/weights/best.pt` | mAP50 0.9794，Phase 2 最优，被 Step9 选用 |
| Step6 | `step6/upload/20260629_115033_P3/model/` | **最终提交的推理模型**（512，去 NMS） |
| Step9 | `step9/upload/model/` | 多框模型（未提交，CPU-only） |

> **Step7 的注意点**：最终训练**从 Step4 权重重新开始**（而不是用 R2 的 `model_v2`），只在 `data4` 上跑 20 epoch。所以"自举迭代"的产物（`model_v1`、`model_v2`）**没有进入最终模型** —— 它们只用于生成伪标签。
