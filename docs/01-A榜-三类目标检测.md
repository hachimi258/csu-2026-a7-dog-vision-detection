## 目的

## 实现：训练工具链设计（`train_tool/`）

`train_tool` 是一套**封装好的 PaddleDetection 训练调度器**，核心思路是把实验配置全部外置到 JSON。

### `train_single.py`（单次训练）

| 参数 | 默认值 | 说明 |
|:---|:---|:---|
| `--exp-name` | 必填 | 实验名，决定输出目录 |
| `--config-template` | `ppyoloe_plus_crn_s` | 模型配置模板 |
| `--epochs` | 200 | |
| `--batch-size` | 8 | |
| `--lr` | 0.005 | → 覆盖 `LearningRate.base_lr` |
| `--warmup-epochs` | 5 | → 覆盖 `LearningRate.schedulers[1].epochs` |
| `--input-size` | 640 640 | |
| `--aug-level` | medium | |
| `--pretrain-weights` | COCO 预训练 | |
| `--save-interval` | 10 | snapshot_epoch |
| `--num-workers` | 4 | |
| `--device` | 0 | |
| `--resume` | 断点续训 | |
| `--dry-run` | 强制 5 epoch | 快速验证 |

流程：`build_train_command()` 用 `-o` 动态覆盖 PaddleDetection 配置 → `tools/train.py`（带 `--eval`）→ `parse_best_metrics()` 正则解析日志提取每轮 `bbox_mAP` 与最佳 epoch → `evaluate_model()`（`--classwise`）→ `export_model_step()` 导出推理模型 → 写 `experiment_summary.json`。

## 实现：最终提交方案

**模型**：PP-YOLOE+ CRN-S（`arch: YOLO`），参数量 ~15M，`model.pdiparams` 28.6 MB + `model.pdmodel` 164 KB。

**推理脚本**（`submission/predict.py`，180 行）：

```python
# 模型加载
config = Config(model.pdmodel, model.pdiparams)
config.enable_use_gpu(2000, 0)      # 2000MB 显存，device 0
config.switch_ir_optim(False)       # ⚠️ 关闭 IR 优化（关键）
config.disable_glog_info()
config.enable_memory_optim()
config.switch_use_feed_fetch_ops(False)
paddle.enable_static()
```

**预处理**（来自 `infer_cfg.yml`，走 PaddleDetection 官方 `preprocess()`）：

| 步骤 | 参数 |
|:---|:---|
| `Resize` | `target_size: [640,640]`，`keep_ratio: false`，`interp: 2`（双线性） |
| `NormalizeImage` | `mean: [0,0,0]`，`std: [1,1,1]`，`norm_type: none` |
| `Permute` | HWC → CHW |

**模型 I/O**：3 输入 `image [1,3,640,640]` + `im_shape` + `scale_factor`；输出 `boxes [N,6]`（`[class_id, score, x1, y1, x2, y2]`）+ `boxes_num`。注意模型导出的静态图**已内含 MultiClassNMS**。

**后处理**：

```python
threshold = 0.45                    # 脚本内硬编码
type = int(class_id) + 1            # 0-index → 1-index（battery=1, board=2, fire=3）
x, y, w, h = x1, y1, x2-x1, y2-y1
```

## ⚠️ A 榜遗留问题（原文档未提及）

**提交包的 `infer_cfg.yml` 里 `label_list` 仍是 COCO 的 80 类**（`person, bicycle, car, ... toothbrush`），而不是 `battery/board/fire`。

**为什么没有导致失败**：`predict.py` 从不读取 `label_list`，`type` 字段直接由 `class_id + 1` 数值计算，而类别数已固化在权重中（`configs/dataset.yml` 是 `num_classes: 3`）。所以 80 类名只是"死配置"，纯粹是导出时忘了替换。**这是一个高风险巧合，不是设计**。

另外 `7.19/A榜_model/infer_cfg.yml`（1211 B）与提交包完全一致（同样 80 类），说明这个配置从导出起就没被修正过。对比 `7.19/B榜_model/infer_cfg.yml` 只有 0.3 KB 且 `label_list: [firebig]` —— B 榜的 `infer_cfg.yml` 是脚本生成的（`step7/tool/pack.py` 会写入），所以正确；A 榜直接用了 PaddleDetection 导出的原始文件。

## 结论

A 榜以 PP-YOLOE+ CRN-S 在 640 输入、`keep_ratio: false`、内置 MultiClassNMS + 脚本内硬编码 0.45 阈值下，取得平台 **F1 0.85396 / FPS 22.6**，两项门槛均达标（FPS 仅超线 13%）。训练侧预设的六阶段超参扫描实际只执行了 Phase 1 的三个 baseline。提交包遗留 `label_list` 仍为 COCO 80 类的死配置问题，因其从未被 `predict.py` 读取而侥幸未致失败。
