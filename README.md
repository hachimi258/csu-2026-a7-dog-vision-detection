# 2026 中国软件杯 A7 · 基于机器狗的视觉目标检测 —— 项目成果档案库

<p align="center">
  <b>一个只有 100 张真实标注的目标检测项目，如何把 FPS 从 14.35 提到 58.28，又为什么最终 F1 只有 0.37529</b>
</p>

---

## 这是什么

这不是一份赛题解答，而是一个**工程复盘档案库**。项目参加了 2026 中国软件杯 A7 赛题（宇树 Go2 Edu 机器狗 + 百度飞桨 PaddlePaddle 视觉平台，AR 增强现实模拟消防侦察），在 A/B 两榜上共迭代了 **9 个 B 榜阶段**，留下了完整的代码、日志与产物。

本仓库把那次项目的**成果、指标、方法、以及全部踩坑与勘误**按"成果主线"重组归档，供学习与复用。

> **本项目最核心的两个数字对比**：
> - A 榜：**F1 0.85396 / FPS 22.6** —— 两项门槛均达标 ✅
> - B 榜：**F1 0.37529 / FPS 58.28** —— 速度解决了，精度没有
>
> 而 B 榜的**本地**验证 F1 是 0.9749。**本地与平台差 2.6 倍** —— 这个差距的成因，是整个复盘里最值得读的部分。

## 成果速览

### 平台实测成绩（唯一权威指标）

| 阶段 | 架构 | 输入 | 后处理 | 平台 F1 | 平台 FPS | 综合 |
|:---|:---|:---|:---|:---|:---|:---|
| **A 榜** | PP-YOLOE+ CRN-S | 640 | 内置 NMS + 0.45 阈值 | **0.85396** | **22.6** | ✅ |
| B 榜 Step5 | YOLOv8m | 640 | NMS(0.45) + 面积 argmax | — | ❌ **14.35** | ❌ 强制 0 |
| **B 榜 Step6** | YOLOv8m | **512** | **去 NMS + 面积 argmax** | **0.37529** | **58.28** | ✅ |
| B 榜 Step7/8/9 | YOLOv8m（多框） | 640 | 面积 argmax（+竖棍降级） | **未提交** | — | — |

速度门槛为 **FPS ≥ 20**（低于则综合分强制为 0）。**只有 A 榜与 B 榜 Step6 有平台成绩。**

### 技术链路

```
数据：2827 张无标注 + 100 张真实标注
  │
  ├─ Step1  教师模型：torchvision Faster R-CNN（ResNet50-FPN-v2）
  ├─ Step2  一次推理 + 离线调阈值 → 配方 thr_095×3 + thr_080×1 = 5313 行
  ├─ Step3  切换到 Ultralytics YOLO，选型 YOLOv8m（mAP50 0.8886）
  ├─ Step4  超参网格：AdamW + lr 1e-4（mAP50 0.9888，但排名是噪声）
  ├─ Step5  PyTorch → ONNX → X2Paddle → Paddle 静态图（含 3 个补丁）
  ├─ Step6  去 NMS + 512 重导出 → 平台 FPS 58.28（+306%）✅
  ├─ Step7  HSV 规则标注失败 → 两轮自举 + 9 张人工难例
  ├─ Step8  15 轮多框自举 → 339 张人工多框标注（最有价值的副产品）
  └─ Step9  多框模型转换 + "竖棍幻觉框"三级降级算法
```

## 五个最值得读的发现

### 1️⃣ 本地 0.9749 vs 平台 0.37529 —— 评估方法论是最大的坑

训练集 **98.7% 是伪标签**（5313 / 5383），只有 70 张真实监督。更糟的是：**`sample100` 的伪标签就是由在 `sample100` 上训练的模型生成的** —— 本地验证等于"用模型自己的输出验证模型自己"。

> 📖 [docs/07-B榜-Step6-速度优化.md](docs/07-B榜-Step6-速度优化.md) · [lessons/复盘-做对了什么做错了什么.md](lessons/复盘-做对了什么做错了什么.md)

### 2️⃣ 「竖棍形幻觉框」—— 赛制规则被模型 reward hack

多框模型会输出**细高条状的幻觉框**（`h/w` 极大），而它的**面积常常是最大的**。赛制要求"面积最大的火焰"，于是这些幻觉框抢占了输出位。**修复前 196 张图（6.9%）的最终输出框是竖棍形**。

修复方案是把"面积 argmax"升级为**带形状先验的面积 argmax**（`STICK_RATIO_3X=3.0` / `STICK_RATIO_6X=6.0` 三级降级，保证永远有输出）。

> 📖 [docs/10-B榜-Step9-竖棍幻觉与可视化核验.md](docs/10-B榜-Step9-竖棍幻觉与可视化核验.md)
>
> 这是**原始文档几乎完全没记录**的发现，也是"面积最大"这类规则漏洞的典型案例。

### 3️⃣ Step8 全部 15 轮的 `--iou 0.9` 从未生效

`step8/tool/train.py` 的 **OOM 重试分支漏传 `iou`**，而所有 12 个 train 日志都写着 `Batch used: 8` —— 铁证表明**每一轮都走了 OOM 分支**，`iou` 全部静默回退到 0.7。

于是原文档中"Phase 2 = IoU 0.9 优于 Phase 3 = IoU 0.7"的整个对比实验，**在方法学上不成立**。

> 📖 [docs/09-B榜-Step8-多框感知三阶段自举.md](docs/09-B榜-Step8-多框感知三阶段自举.md)

### 4️⃣ 跨框架转换：3 个补丁、5 个产物版本、一处技术债失传

PyTorch → ONNX → X2Paddle → Paddle 静态图链路上有 3 个必须的补丁。其中**补丁 #3（DFL Slice 索引硬编码）在 Step6 被手工应用并验证有效**（GPU FPS 58.28），但**Step9 重新转换时没有沿用**，导致 Step9 的静态图 GPU 推理输出全零、只能 CPU 运行（本地 10.81 FPS，远低于门槛）。

> 📖 [code/02-X2Paddle补丁记录.md](code/02-X2Paddle补丁记录.md)

### 5️⃣ 三处"配置存在但完全无效"的实验

`Exp-D2_weighted`（加权损失）、`Exp2-B`（标签平滑）、`Exp2-E`（伪标签权重衰减）**在代码层面与对照组功能完全相同** —— 变量从未被损失函数消费。而原文档的"标签平滑有害"结论正是基于其中两个相同实验的比较。

> 📖 [docs/03-B榜-Step2-数据工程与伪标签配方.md](docs/03-B榜-Step2-数据工程与伪标签配方.md)

## 原文档勘误

项目原有的 `context/S*conclusion.md` 系列是上下文压缩后的产物，**存在多处与代码/日志/产物不符的表述**。本归档逐项核对后整理了 **31 条勘误**，包括：

- 1 处**架构性错误**（称教师模型是 "YOLOv5-like"，实为 Faster R-CNN ResNet50-FPN-v2）
- 12 处**逻辑/机制错误**
- 3 处 **X2Paddle 补丁描述错误**
- 15 处**数值/事实错误**

> 📖 [lessons/原文档勘误清单31条.md](lessons/原文档勘误清单31条.md)
