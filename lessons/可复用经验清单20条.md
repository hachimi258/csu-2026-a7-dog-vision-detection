# 可复用经验清单（20 条）

> **归档说明**：本文由项目全程技术复盘按"成果主线"重组而成，对应原复盘文档的相关章节（源文件 `archive/26中国软件杯_项目全程复盘.md`）。
> **性质**：基于代码、日志、产物实测的复盘记录，**非该阶段原始源码**；文中的代码片段为**原样节选（excerpt）**。

| # | 经验 | 适用场景 |
|:---|:---|:---|
| 1 | **加权采样必须物理化**：清单里的重复行会被按文件去重的加载器静默吞掉，要复制文件并唯一命名 | 任何"数据加权/过采样"需求 |
| 2 | **跨框架转换后必须 CPU + GPU 双向验证** | PyTorch→Paddle / →ONNX / →TRT |
| 3 | **PIR `.json` 与旧 `.pdmodel` 不通用**：转换环境要匹配推理环境的 Paddle 版本 | Paddle 2.x vs 3.x |
| 4 | **改输入尺寸 = 必须重导出模型**（检测头网格数硬编码） | 任何 grid-based 检测器 |
| 5 | **异常/重试分支必须传齐所有参数**，否则参数静默回退默认值 | 所有带 OOM/异常重试的训练脚本 |
| 6 | **验证集必须 ≥100 张，且最好与被评测集同分布** | 一切模型选择 |
| 7 | **本地指标只能做功能验证，不能做精度判断**（若分布不同） | 竞赛/私有评测集场景 |
| 8 | **每次关键决策前先拿一次真实平台反馈** | 有提交机会时 |
| 9 | **评估代码比训练代码更需要 review**：匹配逻辑必须绑定 image id | 所有检测/检索评估 |
| 10 | **"配置存在" ≠ "配置生效"**：消融实验每个变量加运行时断言 | 任何消融/超参搜索 |
| 11 | **"面积最大"这类规则要配形状/语义先验**，否则模型会 reward hack | 单目标选择类后处理 |
| 12 | **Windows 下 YOLO 用目录格式（`train: train`），不用 `train.txt`** | Windows + Ultralytics |
| 13 | **`amp=False` 可避免 AMP check 下载模型造成的启动卡顿**，但会让结果与其他配置不可比 | 离线/网络受限环境 |
| 14 | **`cv2.imread` 不支持中文路径**，用 `np.frombuffer` + `cv2.imdecode` | Windows 中文路径 |
| 15 | **收敛判定流水线要严格串行**：训练完成 → 推理 → 判定 → 合并，且日志时间戳可验证 | 自举/迭代式训练 |
| 16 | **规则方法（HSV 等）需要面积/形状先验和负样本约束**，否则会把整个数据集标成正样本 | 传统 CV 标注方案 |
| 17 | **过采样时用 `defaultdict(int)` 严格计数，并在 rebuild 前清空输出目录** | 多次迭代的数据集构建 |
| 18 | **长跑训练前先检查系统资源**（僵尸进程会让训练慢 100 倍） | 多轮连续训练 |
| 19 | **不要用 `resume=True` 改超参**（Ultralytics 会从 checkpoint 恢复全部原始参数） | Ultralytics |
| 20 | **数据集划分要用补集而非独立组装**，否则会产生 train/val 重叠 | 任何带采样的数据划分 |
